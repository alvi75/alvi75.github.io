A Systematic Literature Review of Parameter-Efficient Fine-Tuning for Large Code Models

Surveying 28 studies, 19 software engineering tasks, and four families of PEFT methods to map how parameter-efficient fine-tuning is reshaping the way we adapt large code models.

ACM Transactions on Software Engineering and Methodology (TOSEM), 2026 · DOI: 10.1145/3796522

Saima Afrin*, Md Zahidul Haque*, Antonio Mastropaolo  ·  *equal contribution

In short
  • Most PEFT work in software engineering targets code summarization and code generation, on encoder-decoder models such as CodeT5, with LoRA as the most used method.
  • Where a study compares PEFT with full fine-tuning of the same model, PEFT usually matches or beats it. Code translation and clone detection have the most results where it does worse.
  • The evidence still has gaps in both methods and tasks; Section 6 lists them.

1. The Problem: Full Fine-Tuning Doesn't Scale

Large code models (LCMs) — CodeLlama, DeepSeek-Coder, CodeT5, StarCoder, and the rest of the family — have pushed code intelligence forward across nearly every software engineering task we care about. But getting these models to do something useful for your task usually means fine-tuning, and full fine-tuning is expensive: every weight is updated, every gradient is held in memory, and every task gets its own full copy of the model.

Parameter-efficient fine-tuning (PEFT) freezes most of the model and trains a small part instead. Figure 1 shows how. PEFT is well studied in NLP; this review maps how it is used for code.

2. What We Did: A Systematic Review

We followed Kitchenham's guidelines for systematic literature reviews. We searched IEEE Xplore, the ACM Digital Library, Springer Link and Google Scholar for 2019–2025, with search strings that pair PEFT terms with all 23 task names from Watson et al.'s taxonomy of deep learning for software engineering. Preprint servers were left out of the database search.

Three research questions structure the review:

  • RQ1: Which software engineering tasks have been explored using PEFT methods?
  • RQ2: Which deep learning models and architectures are commonly optimized with PEFT methods?
  • RQ3: How do PEFT methods affect task performance and training efficiency compared with full fine-tuning?

3. RQ1 — Which SE Tasks Use PEFT?

Code summarization and code generation lead by a wide margin, and 17 of the 28 studies apply PEFT to more than one task. Generative tasks split by what goes in and what comes out: code-to-code tasks such as translation, refinement and repair appear in 21 studies, code-to-text tasks in 16, and text-to-code tasks in 12. Almost all non-generative work is classification; code search is the only ranking task, and no study uses regression.

4. RQ2 — Which Models and PEFT Methods?

Architectures. Encoder-decoder models appear in 29 task instances across 12 studies, encoder-only models in 22 across 10, and decoder-only models in 19 across 12. CodeT5 is the most adapted single model (19 task instances in 8 studies), followed by GraphCodeBERT, CodeBERT, PLBART and UniXcoder. Decoder-only models such as the CodeLlama family appear only in generative tasks.

Methods. Base LoRA is the most used technique (29 task instances), followed by the adapter family (23), Prompt Tuning (14), Prefix Tuning (13) and P-Tuning (7).

How LoRA is configured. Generative tasks typically use rank 8 or 16 on the attention layers, or on attention and feed-forward layers. Non-generative tasks often use lower ranks (1, 4 or 8), keeping the trained share well below 1%, except for FF-LoRA set-ups that adapt only the feed-forward layers with ranks of 256 or 512. Adapter studies often leave out their configuration, which makes them hard to compare.

5. RQ3 — How Does PEFT Compare to Full Fine-Tuning?

Only 20 of the 28 studies compare a PEFT method with full fine-tuning of the same base model.

LoRA-based methods are the most common winners on generative tasks, and every QLoRA entry reports both better performance and better efficiency. Code translation may be less suited to PEFT: Base Adapter, FF-LoRA + AT and MAM all translate worse than full fine-tuning, and only Prompt Tuning translates better. Among non-generative tasks, defect detection is better in three of its four entries and on par in the fourth, while code clone detection is split evenly between better-or-similar and worse. Prompt Tuning reports better performance in every entry it has.

One study (Wang et al.) adds a caution: PEFT holds up on public code but drops markedly on private codebases, where the needed knowledge is far from the pre-training data.

6. What Future Work Should Do

The paper closes with six steps for future studies, each with a note on what to report:

  1. Cover the missing tasks. Software testing, documentation generation, code quality assessment, API recommendation, automated refactoring and requirements analysis are barely studied. A single PEFT set-up that works across tasks is also worth trying.
  2. Match the base model to the task. Justify the architecture, model size and pre-training data; larger models like StarCoder-15B and DeepSeek-Coder-33B are still underused.
  3. Try more PEFT methods. Several methods still have no head-to-head result (Figure 7), newer LoRA variants such as LoRA-pro and LoRA-GA are untried in SE, and hybrids like LoRA + Prefix Tuning deserve a closer look.
  4. Measure more than accuracy. Report memory and latency against full fine-tuning, generalization across tasks and languages, low-resource behavior, and ablations.
  5. Make results reproducible. Share scripts, data and checkpoints, document hardware and training steps, and use shared benchmarks so methods can be compared side by side.
  6. Study domain-specific knowledge. Separate public from private data in evaluations, report how far the data shifts from pre-training, and look for PEFT variants that can learn knowledge the base model never saw.

7. What It Means

For practitioners, the paper names Base LoRA as the first choice when results need to match full fine-tuning. For code generation the paper recommends decoder-only models, and for a mix of analysis and generation, encoder-decoder models. Generative tasks show the clearest return on PEFT, so they are the place to start.

More broadly, the review argues that PEFT is not just a workaround for scarce GPUs but a practical way to adapt large code models in its own right.
